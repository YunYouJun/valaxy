# 云栈统一编辑器与 Valaxy 第一方支持

状态：产品方向已收敛；当前 Valaxy Electron 预览版尚未迁移到 CMS。具体任务以 `YunLeFun/cms/specs/valaxy-first-party-client/` 下的需求、设计和任务为准，本文件只保留产品与视觉参考。

## 产品与仓库归属

云栈是唯一编辑器产品，Web、桌面和手机入口均在 CMS 仓库实现。文章管理、编辑、字段、媒体、草稿、同步、冲突和发布交互维护一份，按设备调整布局。

Valaxy 由云栈第一方支持，包括项目创建/导入、内容模型、站点配置、主题与 Addon 的支持范围、预览、构建和部署。首版以官方模板与 Yun 主题为兼容基线，自定义配置和未支持语法保留原内容并说明能力范围。

Valaxy 仓库保留框架、CLI、主题、DevTools 和通用接口。现有 Electron 实现迁入 CMS；本仓库不再增加客户端产品功能。迁移验收前保留原资产，之后清理旧包与安装包 CI。

`valaxy-addon-ylf-cms` 不再是本轮目标。云栈内置第一方适配与可选云同步，基础本地写作无需登录。

## 一套编辑体验与平台差异

| 入口 | 主要体验 | 运行能力 |
| --- | --- | --- |
| 云栈 Web | 在线写作、站点管理、草稿与发布 | 内容净化预览；PR 与独立 CI |
| 云栈桌面 | 本地离线写作、完整博客创建与管理 | 文件、凭据与独立子进程；真实 Valaxy 预览/构建 |
| 云栈手机 | 随手写作、照片、草稿接续与发布 | 同一内容工作台的手机布局；原生存储与系统能力 |

共享范围覆盖工作台和草稿逻辑，而不仅是编辑框。先在 CMS 内部 workspace 抽离、让 Web 回接，再迁移桌面。包的公开发布和通用插件 SDK 不作为前置任务。

CMS 服务端、Web 和手机不执行仓库配置、主题、Addon 或脚本。桌面本地执行适用范围与现有 CMS 规范在新计划 P0 中明确；归入同一仓库不意味着服务端可以执行这些代码。

## 视觉参考

现有桌面视觉以 Valaxy 官网为品牌来源，参考 [Vite 官网](https://vite.dev/) 的分栏、留白和细线结构。合入云栈时复用已有品牌与工作台样式，不另造第二套写作 UI。

- 保留 Valaxy 官方标志作为框架标识，产品名称统一为云栈。
- 浅色参考：纸白 `#ffffff`、背景 `#f8f9fc`、正文 `#202331`、次级文字 `#626777`。
- 品牌参考：主色 `#5468c4`、强调色 `#8546ef`；渐变限于品牌和主要操作。
- 字体参考：Avenir Next / 系统无衬线字体；路径、版本与状态辅助信息使用等宽字体。
- 编辑区域保持安静；桌面分栏与快捷键，手机单栏、触控工具条和独立内容设置页。
- 跟随系统明暗模式，状态需有文字提示，不只靠颜色；未实现能力不放置虚假可用入口。

当前 `WelcomeWorkspace`、`ProjectSidebar`、`ProjectWorkspace` 是可复用的原型材料；其存在不代表应继续维护独立 Valaxy 客户端界面。

## 数据与发布原则

Git 是已提交内容的来源，云栈维护共享草稿版本，本地保存工作副本。首轮同步即提供持久队列，明确区分“本机已保存”“云端已同步”“已发布上线”。

同步携带版本与幂等请求 ID，冲突保留双方；正文、元数据、媒体、改名和删除均需纳入一致性。只同步明确授权的内容，不同步凭据、依赖、缓存或任意可执行文件。首次导入展示变更，不覆盖未提交修改。

Web/手机发布沿用 PR 与独立 CI；桌面本地直传作为显式选择。PR 创建、合并、部署成功分别展示，线上状态关联确定的内容版本。手机可在桌面关闭时继续编辑和经已有 CI 发布。
